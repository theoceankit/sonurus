# Audit — September 2026

Full technical audit of the codebase conducted 2026-09-27 against `main` (commit `9c2f343`). Covers the FastAPI backend (`app/`), Electron main process (`electron/main.js`, `preload.js`, `backend.js`) and all renderer modules. All items from the [June 2026 audit](./audit-2026-06.md) were already closed; this document lists only new or previously unaddressed findings.

Use this document as an execution checklist. Mark each item `✅` when the fix is merged to `main`.

Items marked **Verified** were reproduced (script or test), the rest were found by code reading.

**Not covered in depth:** `electron/renderer/setup.html`, CSS, `scripts/bundle-backend.js`, `native/macos/sonorus-capture`, CI build workflow.

## Section 1 — Bugs & Correctness

### 1.1 Linux system-audio capture deadlocks after ~5 minutes

**Severity:** Critical · **Verified**
**File:** `app/services/audio_capture_service.py` — `start_capture()`, `stop_capture()`

`ffmpeg` is spawned with `stdout=PIPE, stderr=PIPE`, but nothing reads the pipes. ffmpeg writes a stats line to stderr every 0.5 s; once the 64 KB pipe buffer fills, ffmpeg blocks on `write()` and stops capturing audio. On stop, `SIGINT` cannot unblock it and `process.wait()` (no timeout) hangs forever — the HTTP request never returns and the UI stays on "Stopping…".

**Fix:** run ffmpeg with `-nostats -loglevel error`, redirect stdout to `DEVNULL` and stderr to a temp log file (or a draining thread), and use `wait(timeout=…)` with a `kill()` fallback.

### 1.2 Live recordings are stored in the OS temp directory

**Severity:** Critical
**Files:** `electron/main.js` (`save-recording` IPC), `app/services/audio_capture_service.py` (`start_capture`, `_merge`)

Recorded audio is written to `os.tmpdir()` / `tempfile.gettempdir()` and that path is persisted as `transcriptions.audio_file`. On systems where `/tmp` is `tmpfs` the file disappears on reboot, so the editor can no longer play the recording. `ArchiveService` copies the audio to `.files/…`, but the DB path is never updated to the archived copy. Intermediate files (`sonorus-sys-*`, `sonorus-rec-*`, `sonorus-merged-*`) are never deleted.

**Fix:** store recordings under `$SONORUS_DATA_DIR/recordings/` (or point `audio_file` at the archived copy after `archive()`), and delete intermediate capture files after merge.

---

### 1.3 Stale memory instance in the pipeline overwrites speaker renames

**Severity:** Critical · **Verified**
**Files:** `app/api/routers/transcription.py` (`_run`), `app/services/speaker_memory_service.py` (`SpeakerRepository.save`)

Each job builds its own `SpeakerMemoryService` at job start. When the job finishes, `commit_recognized_speakers()` → `save()` rewrites **all** names from that snapshot (`DELETE` + `INSERT` for every named speaker). A rename made in the UI while the job was running is reverted. The same path can also resurrect names of speakers removed during the job.

**Fix:** `save()` must only write names that were changed through this instance (dirty tracking for names, as already done for embeddings), or the pipeline must commit through the shared API instance / reload before committing.

**Test:** rename via the API instance while a second instance is alive → commit through the second instance → name in DB must be the new one.

---

### 1.4 Model download progress freezes with two concurrent downloads

**Severity:** High
**File:** `app/api/routers/models.py`

The WebSocket handler reads the progress queue via `loop.run_in_executor(_executor, q.get)` — the same `ThreadPoolExecutor(max_workers=2)` that runs the downloads. With two downloads active both workers are busy, so no progress events and no heartbeats reach the UI until one download finishes.

**Fix:** use an `asyncio.Queue` fed with `call_soon_threadsafe` (as `transcription.py` does), or read with `asyncio.to_thread` on the default executor.

---

### 1.5 Download cancel does not cancel; interrupted downloads look installed

**Severity:** High · **Verified** (against `huggingface_hub` 0.36.2 source)
**File:** `app/services/model_service.py` — `download_model()`, `is_installed()`

`cancel_event` is only checked before and after `snapshot_download()`, so a cancelled download keeps running to completion in the background. `is_installed()` checks for `refs/main`, which `snapshot_download()` writes **before** downloading any file — a download interrupted by quitting the app leaves the model reported as installed, and the next transcription fails when loading it.

**Fix:** pass a `tqdm_class` that raises on `cancel_event` to abort the transfer; determine installation by the presence of the expected snapshot files (e.g. `model.bin` for Whisper) or write a completion marker after a successful download.

---

### 1.6 Deleting a transcript leaves its voice in speaker profiles

**Severity:** High
**Files:** `app/api/routers/transcripts.py` (`delete_transcript`, `delete_segment`), `app/services/transcript_storage_service.py` (`delete`)

Deleting a transcript or segment removes DB rows but does not call `CommitService.recompute_or_remove()` for the affected speakers. Their stored embeddings still include the deleted audio, and unnamed speakers that existed only in that transcript remain in memory forever and keep matching new recordings. Violates the intent of invariant I4.

**Fix:** collect the effective speaker IDs before deletion and call `recompute_or_remove()` for each afterwards.

---

### 1.7 Editor playback restarts on every edit for non-ASCII paths

**Severity:** Medium
**File:** `electron/renderer/views/editor-view.js` — `buildEditor()`

`audio.src !== 'file://' + transcript.audio_path` compares the browser-normalised (percent-encoded) URL with a raw string. For paths with spaces or non-ASCII characters (e.g. Cyrillic) the check is always true, so `src` is reset — and playback interrupted — on every editor rebuild. A `#` in the filename breaks loading entirely; Windows paths produce an invalid `file://C:\…` URL.

**Fix:** build the URL with a proper file-URL encoder (e.g. `encodeURI` per path segment, `file:///` prefix for drive letters) and compare against the normalised value.

---

### 1.8 "Add new speaker" from a segment row reassigns every segment

**Severity:** Medium
**File:** `electron/renderer/views/editor/speaker-picker.js`

When the picker is opened from a segment row (`segmentStart !== null`), choosing an existing speaker updates only that segment, but "Add new speaker" always calls `POST /reassign`, moving **all** segments of the current speaker.

**Fix:** for the single-segment case, create the speaker and then `PATCH` only that segment (requires a backend endpoint that creates a named speaker, or `to_speaker_name` support on the segment endpoint).

---

### 1.9 Segment text edit: Escape saves, no error check

**Severity:** Medium · **Verified** (in the running app)
**File:** `electron/renderer/views/editor/segment-row.js` — `commitEdit()`, `cancelEdit()`

- The `PATCH …/text` response is not checked for `r.ok`; on a server error the UI shows the new text as saved.
- `cancelEdit()` hides the focused `contenteditable`, which fires `blur` → `commitEdit()`: pressing Escape **saves** the edit it was meant to discard. (A double PATCH on Ctrl+Enter was suspected but did not reproduce — by the time the blur fires, `seg.text` already holds the new text.)

**Fix:** check `r.ok`; clear the `editing` flag before hiding so the blur re-entry is a no-op.

---

### 1.10 Per-segment embedding may belong to a different speaker

**Severity:** Medium
**File:** `app/services/transcript_builder.py` — `attach_embeddings()`

The embedding is chosen by maximum time overlap only, ignoring the diarization speaker. A Whisper segment spanning a speaker change can receive the other speaker's embedding, which then contaminates the profile of the segment's speaker on commit.

**Fix:** only consider overlapping diarization turns whose `speaker` equals `seg.speaker_raw`; no such turn → no embedding.

---

### 1.11 GPU memory is not released after a failed or cancelled job

**Severity:** Medium
**File:** `app/api/routers/transcription.py` — `_run()`

Model teardown (`model = None`, `inference = None`, `gc.collect()`, `torch.cuda.empty_cache()`) runs only on success. After an error or cancel, VRAM stays allocated until the next job.

**Fix:** move teardown into `finally`.

---

### 1.12 A WebSocket disconnect cancels the transcription job

**Severity:** Medium
**File:** `app/api/routers/transcription.py` — `ws_progress()`

`WebSocketDisconnect` sets the job's cancel event. Reloading the renderer or a transient disconnect cancels every queued job.

**Fix:** do not cancel on disconnect (cancellation is explicit via `DELETE /transcribe/{id}`); allow the client to reconnect to a running job.

---

### 1.13 Minor editor state bugs

**Severity:** Low
**Files:** `electron/renderer/views/editor/right-panel.js`, `player-bar.js`, `editor-view.js`

- Speaker preview audio keeps playing after leaving the editor (`root._cleanup` pauses only the main player).
- `audio.volume` is reset to `0.8` on every editor rebuild.
- The speed button label resets to `1×` on rebuild while `audio.playbackRate` keeps the previous value.

## Section 2 — Security

### 2.1 `save-recording` IPC trusts a renderer-supplied extension (carry-over of June 2.5)

**Severity:** Low (defence in depth)
**File:** `electron/main.js`

`path.join(os.tmpdir(), \`sonorus-rec-${uuid}.${ext}\`)` with `ext = '/../../..'` resolves outside the temp dir — arbitrary file write from the renderer.

**Fix:** whitelist `ext` (`webm`, `wav`).

## Section 3 — Dead / Unused Code & Non-functional UI

### 3.1 Recording modal toggles are ignored

`recordingDiarize` and `recordingSaveAudio` ("Diarize speakers", "Save audio file") are persisted but never used by the recording or transcription flow. Either implement or remove. — `views/new-recording-modal.js`

### 3.2 Export settings are ignored

Export format (md/srt/vtt/json) and the timestamps/speakers/bookmarks/audio/duplicate toggles in Settings have no effect; the titlebar export copies plain text scraped from the DOM. — `views/settings-view.js`, `app.js`

### 3.3 Sidebar filters and search are stubs

`_applyFilter()` filters on `r.source`, which the API never returns — "Notes" is always empty. `_rerenderList(query)` is never called with a query; the titlebar search is a label only. — `app.js`

### 3.4 Unused backend code

- `TranscriptStorageService.get_embeddings_by_speaker()` (tests only)
- `SpeakerMemoryService.find_by_name()` / `SpeakerRepository.find_by_name_in_db()` (tests only)
- `POST /transcripts/{id}/commit` and `CommitService.commit()` — not called by the frontend
- `known_speakers` parameter of `SpeakerRepository.save_names_only()`
- Windows branch of `AudioCaptureService` (`-f wasapi` is not an ffmpeg input device; Windows uses the renderer loopback path)
- `converter.py` — not referenced anywhere

### 3.5 Unused frontend code

- `_liveSession.elapsed` (always 0) and the `elapsed` local in `_stopLiveRecording()` — `app.js`
- `getDisplayName()` — `right-panel.js`
- `row.dataset.edit` — `segment-row.js`; `srcChip.style.cssText = ''` — `editor-view.js`
- Legacy `spk_` fallback in `isUnrecognized()` — `utils.js`

### 3.6 Waveform is decorative

Bar heights are pseudo-random, not derived from the audio. — `views/editor/waveform.js`

## Section 4 — Performance

### 4.1 No indexes on `segments`

`segments(transcription_id)` and `segments(speaker_id)` are unindexed; every embedding recompute scans the whole table including BLOBs. — `app/db/schema.py`

### 4.2 Embeddings loaded where they are not needed

`GET /transcripts/{id}` and `DELETE /transcripts/{id}` call `storage.load()`, which deserialises every segment embedding. Add a lightweight `exists()` / load without embeddings.

### 4.3 Models reloaded for every job

Whisper, the embedding model and the diarization pipeline are loaded from disk for each job (tens of seconds). Cache the controller between jobs with the same Whisper model, releasing it after an idle timeout.

### 4.4 Full editor rebuild after every action

Every speaker/segment action triggers three requests, a full editor rebuild and a sidebar reload; each row creates five buttons with their own tooltip listeners. Noticeable on long recordings.

### 4.5 `attach_embeddings()` is O(N×M)

Both lists are time-sorted; a two-pointer sweep makes it linear.

## Section 5 — Readability & Refactoring

### 5.1 `knownMap` is built six different ways

`editor-view.js`, `speaker-card.js`, `speaker-picker.js`, `player-bar.js`, `right-panel.js` (different shape: `id → name`) and `app.js` each rebuild it. Build once in `buildEditor()` and pass it down.

### 5.2 Speaker memory access

- The reassign endpoint calls the private `memory._generate_new_speaker_id()`.
- Two `SpeakerMemoryService` instances (API singleton + per-job) are kept in sync via `reload()` from a worker thread without locking.
- `save()` deletes and re-inserts all names on every call.

### 5.3 Two schema-version mechanisms in one DB

`_meta.schema_version` (speaker tables) and `_ts_schema_version` (transcript tables) live in the same file.

### 5.4 Duplication and small inconsistencies

- Audio-source discovery (`/audio/capture/sources`) duplicated in the recording modal and Settings.
- `_addJob()` derives the title with `split('/')` — breaks on Windows paths (the editor already uses `/[\\/]/`).
- `DIARIZATION_CATALOG` shows "112 MB" while `size_bytes` is 300 MB.
- `cancel_download` hand-builds a Pydantic-style 422 body.
- Unrecognized speakers are labelled "Unknown N" in segments and "Unknown speaker N" in the right panel.

## Section 6 — Tests

### 6.1 Some API tests start real model downloads

Found while fixing 1.4: several tests `POST /models/{id}/download` without patching `snapshot_download`, so real network downloads run in the shared `_executor` (visible as `Download error: small: cannot schedule new futures after interpreter shutdown` at the end of the run). They occupy the download workers across tests and depend on the network.

**Fix:** patch `ModelService.download_model` / `snapshot_download` in every test that starts a download; give tests that depend on worker availability their own executor.
